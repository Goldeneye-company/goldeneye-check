# Участие в разработке

## Ложное срабатывание или пропуск

Создайте issue и приложите фрагмент кода, на котором правило сработало зря или не сработало. Настоящие ключи и пароли замените на `XXXX`.

## Новое правило

1. Добавьте правило в формате opengrep в один из файлов `gecheck/rules/`. В блоке `metadata.ge` укажите `severity` (critical, high, medium или low), `category`, `cwe`, а также `title` и `fix` на трёх языках: `ru`, `kk`, `en`. В `fix` опишите, что нужно исправить.
2. Добавьте пример в `bench/make_fixture.py`: уязвимую строку с маркером `GE:Vnn` и, если возможно, похожую безопасную строку с маркером `GE:Snn`.
3. Запустите тесты и сравнение:

```bash
python -m unittest discover -s tests
python bench/benchmark.py
```

Правило принимается, если оно находит свой пример и не срабатывает на безопасных строках.

## Требования к изменениям

- Программа только читает файлы проекта и не изменяет их. Проверка сайта выполняет только GET-запросы.
- Значения секретов не выводятся целиком ни в консоль, ни в отчёты.
- Исходный код пользователя никуда не отправляется.
