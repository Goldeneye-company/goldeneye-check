# GoldenEye Check

Бесплатная проверка кода и сайта на типовые уязвимости — до того, как их найдут боты.
Для тех, кто пишет код сам или вместе с ИИ (Cursor, Claude, Lovable, Bolt, v0) и хочет выложить проект без дыр.

Отчёт на русском, казахском или английском. **Код не покидает ваш компьютер.**

```bash
gecheck install                 # один раз: скачать движки
gecheck scan .                  # проверить код проекта в текущей папке
gecheck site мой-сайт.kz        # проверить опубликованный сайт (только свой)
```

```
Индекс защищённости: 65/100 · Оценка D
Всего находок: 2 — критично 1, высокий 1, средний 0, низкий 0
→ .goldeneye-check/report.html
```

Пример отчёта: [examples/report-ru.html](examples/report-ru.html) · [қазақша](examples/report-kk.html) · [English](examples/report-en.html)

## Что проверяет

### Код — `gecheck scan`

| Что | Чем | Примеры |
|---|---|---|
| Секреты в коде **и в истории git** | gitleaks | ключи OpenAI, Anthropic, Stripe, AWS, GitHub, Telegram; ключ, который «удалили», но он остался в истории |
| Уязвимые зависимости | osv-scanner | npm, pip, composer, go и другие lock-файлы; версия, до которой обновиться |
| Уязвимости в коде | opengrep + правила GoldenEye | SQL- и NoSQL-инъекции, XSS, внедрение команд, SSRF, обход каталогов, eval, pickle, JWT без проверки подписи, захардкоженные пароли |
| Расходы на ИИ | правила GoldenEye | ИИ-эндпоинт без входа, вызов модели без `max_tokens` или с огромным лимитом |
| Конфигурации | встроенные проверки | `.env` в git, секреты в `NEXT_PUBLIC_`/`VITE_`, таблицы Supabase без RLS, открытые правила Firebase, пароль `postgres` и открытый порт базы в docker-compose, листинг каталогов в `.htaccess` |

Языки: JavaScript, TypeScript (Express, Next.js), Python (FastAPI, Flask, Django), PHP. Список правил: `gecheck rules`.

### Сайт — `gecheck site`

HTTPS и перенаправление на него, срок сертификата, заголовки защиты (HSTS, CSP, nosniff,
защита от встраивания, Referrer-Policy), флаги cookie, версия сервера, случайно открытые файлы
(`.env`, `.git`, дампы баз, `phpinfo.php`, бэкапы) и открытые списки файлов в папках.

Только обычные запросы чтения, как у браузера, около 30 штук с паузой. Ничего не подбирает и не атакует.
**Проверяйте только свой сайт** или сайт, владелец которого разрешил проверку: команда спросит подтверждение.

### Перед запуском — [CHECKLIST.md](CHECKLIST.md)

То, что программа увидеть не может: лимиты расходов на ИИ, двухфакторный вход, бэкапы, права доступа.

## Как это работает

```
gecheck scan
  ├── gitleaks      → секреты в файлах и во всей истории git
  ├── osv-scanner   → уязвимые версии пакетов (в базу OSV уходят только названия и версии)
  ├── opengrep      → анализ потоков данных по правилам GoldenEye
  └── встроенные проверки конфигураций
        ↓
  .goldeneye-check/report.html   — для человека
  .goldeneye-check/report.md     — для репозитория и pull request
  .goldeneye-check/report.json   — для CI: без кода и без секретов
```

- Секреты никогда не попадают в отчёт целиком: `sk_liv…Wc`.
- `--offline` — зависимости проверяются по скачанной базе, в сеть не уходит ничего.
- Движки скачиваются только из официальных релизов, версии и SHA-256 закреплены в коде.

## Установка

Нужен [Python](https://www.python.org/downloads/) 3.9 или новее (при установке на Windows отметьте
«Add python.exe to PATH»). Внешних Python-библиотек нет, git не нужен.

```bash
pip install https://github.com/Goldeneye-company/goldeneye-check/archive/refs/heads/main.zip
```

```bash
gecheck install
```

Первая команда ставит программу, вторая — скачивает движки проверки.

Движки (~135 МБ) кладутся в `~/.goldeneye-check/engines` (папку меняет переменная `GECHECK_HOME`).
Поддерживаются Windows x64, Linux x64, macOS на Apple Silicon.

## Использование

```bash
gecheck scan путь/к/проекту --lang kk          # отчёт на казахском
gecheck scan . --format json --out reports/     # только JSON в свою папку
gecheck scan . --no-history                     # без поиска по истории git (быстрее)
gecheck scan . --offline                        # без обращения к сети
gecheck scan . --fail-on high                   # код выхода 1 при высоких и критичных — для CI
gecheck site мой-сайт.kz --lang en              # проверка сайта, отчёт на английском
```

**Индекс защищённости** = 100 − штраф за код − штраф за зависимости (не ниже 0).
- код, секреты, конфигурации: −25 за критичную, −10 за высокую, −4 за среднюю, −1 за низкую;
- зависимости: −10 / −4 / −1, но в сумме не больше −30 — устаревшие пакеты не обнуляют оценку чистого кода.

Оценка: A — 90+; B — 75+; C — есть высокие в коде, критичные в зависимостях или < 75;
D — есть критичные в коде или < 50; F — < 25.

### В GitHub Actions

```yaml
- run: pip install https://github.com/Goldeneye-company/goldeneye-check/archive/refs/heads/main.zip && gecheck install
- run: gecheck scan . --fail-on critical --format md,json
```

## Насколько хорошо находит

**Учебный проект** (`bench/`): 29 заложенных уязвимостей и 9 безопасных фрагментов-ловушек,
ключи сгенерированы случайно в реальном формате.

| | Нашёл | Ложных срабатываний |
|---|---|---|
| GoldenEye Check 0.1.0 | 29 из 29 | 0 из 9 |
| vibe-audit (MIT, regex-сканер) | 4 из 29 | 0 из 9 |

Учебный проект написан вместе с правилами, поэтому честнее смотреть на **реальные проекты**
([bench/REALRUN.md](bench/REALRUN.md)): OWASP NodeGoat, DVWA, PyGoat, nextjs/saas-starter, fastapi/full-stack-fastapi-template.
Из 72 находок в коде, секретах и конфигурациях верные 67 (≈ 93 %), проверка занимает 4–19 секунд.

Проверку сайта мы первым делом прогнали по своему goldeneye.kz — и нашли, что заголовки защиты
приходили только на служебные запросы, а браузерам — нет.

## Чего программа не делает

Не проверяет логику прав доступа (может ли пользователь A открыть данные пользователя B),
вход и сессии, настройки облачных консолей и платёжных систем, работу под нагрузкой, и не говорит,
затрагивает ли ваш проект уязвимость в зависимости. Это проверка типовых ошибок, а не пентест.
Ноль находок — хороший знак, но не гарантия.
