# Проверка на открытых проектах

Дата: 4 октября 2026 года. Версия: GoldenEye Check 0.1.0, правила 2026.10.0.

Находки в коде, секретах и конфигурациях проверены вручную по исходному коду. Находки по зависимостям вручную не проверялись, они берутся из базы OSV.

| Проект | Описание |

| OWASP NodeGoat | учебное уязвимое приложение на Express |
| DVWA | учебное уязвимое приложение на PHP |
| PyGoat | учебное уязвимое приложение на Django и Flask |
| nextjs/saas-starter | шаблон SaaS на Next.js и Stripe |
| fastapi/full-stack-fastapi-template | шаблон приложения на FastAPI и React |

## Что найдено

- NodeGoat: eval от данных формы (3 места), NoSQL-инъекция через `$where`, отключённое автоэкранирование шаблонов, SSRF, открытый редирект, приватный TLS-ключ в репозитории и в истории, ключ ZAP в конфигурации, пароли в seed-скрипте, 130 уязвимых пакетов.
- DVWA: внедрение команд (уровни low, medium, high и API), SQL-инъекции (sqli, blind, brute, authbypass), JSONP-инъекция, файл базы SQLite в репозитории. На уровне impossible находок нет.
- PyGoat: pickle и `yaml.load` с пользовательскими данными, eval, `shell=True`, `SECRET_KEY` в коде, `DEBUG = True`, ключи Stripe и пароли в истории git.
- saas-starter: тестовый ключ Stripe и секрет вебхука, которые были добавлены в README в сентябре 2024 года и позже удалены, но остались в истории git. Пароль в seed-скрипте (low).
- fastapi-template: файл `.env` с заглушками `changethis` хранится в git (medium), порт базы открыт в `compose.override.yml` (low).

## Что не найдено

| Класс | Пример | Причина |
|---|---|---|
| Логика доступа | IDOR в NodeGoat (allocations по userId), BAC в DVWA | требует понимания бизнес-логики |
| Аутентификация и сессии | слабые пароли, настройки сессий в NodeGoat, CSRF | зависит от настроек фреймворка |
| Потоки данных между файлами | xss_r, xss_s, fi в DVWA | правила работают в пределах одного файла |
| Использование уязвимых функций зависимостей | уязвимость Next.js в статическом сайте | анализ достижимости не выполняется |

## Изменения по итогам проверки

1. RLS проверяется только в проектах на Supabase. Раньше правило срабатывало на миграции Drizzle.
2. Уровень находки «.env в git» зависит от содержимого: critical для похожих на настоящие значения, medium для заглушек, low если секретов нет.
3. Секреты в документации и тестах, а также тестовые ключи Stripe получают уровень medium. Эвристическое правило gitleaks generic-api-key получает high, распознанные ключи сервисов critical.
4. Пароли в seed-скриптах и тестах получают уровень low.
5. В PHP значение после `is_numeric`, `preg_match`, `ctype_digit` и `filter_var` считается проверенным. Это убрало ложные срабатывания на уровнях impossible и BAC в DVWA.
6. Добавлены правила для NoSQL `$where` и отключённого автоэкранирования шаблонов.
7. В отчёте маскируется только значение секрета, а не все строки в кавычках.
8. Ключ, удалённый из файла, который остался в репозитории, теперь отмечается как находка в истории git. Дубли для перемещённых файлов убраны.
9. Штраф за уязвимые зависимости ограничен 30 баллами. Для saas-starter и fastapi-template индекс изменился с 0 (F) на 61 и 60 (C).

Каждое изменение покрыто тестом или примером в учебном проекте.
