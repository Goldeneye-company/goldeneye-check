## Высокий (12)

### docker-compose: пароль базы по умолчанию (POSTGRES_PASSWORD)
- Где: `docker-compose.yml:5`
- Как исправить: Сгенерируйте длинный пароль, передавайте его через .env (не коммитя) и смените на всех серверах, где этот файл уже запускался.
- CWE-1393

### Уязвимая зависимость: lodash 4.17.15
- Где: `package-lock.json`
- уязвимости: CVE-2020-28500, CVE-2020-8203, CVE-2021-23337, CVE-2025-13465
- Как исправить: Обновите lodash до версии 4.18.0 или новее и пересоберите lock-файл.
- CWE-1395

### XSS — данные пользователя выводятся на страницу без экранирования
- Где: `public/contact.php:4`
- Как исправить: Выводите через htmlspecialchars($value, ENT_QUOTES, 'UTF-8').
- CWE-79

### Внедрение заголовков письма — форму можно использовать для рассылки спама
- Где: `public/contact.php:7`
- Как исправить: Не подставляйте ввод в заголовки письма. Адрес проверяйте filter_var(..., FILTER_VALIDATE_EMAIL) и удаляйте переводы строк.
- CWE-93

### XSS — данные пользователя выводятся в HTML без экранирования
- Где: `src/server/users.js:23`
- Как исправить: Экранируйте вывод (шаблонизатор с автоэкранированием, escape-html) или отдавайте JSON. Для HTML от пользователя — DOMPurify.
- CWE-79

### JWT читается без проверки подписи (jwt.decode)
- Где: `src/server/users.js:29`
- Как исправить: jwt.decode только читает токен — подделать его может любой. Для входа и прав используйте jwt.verify(token, secret, { algorithms: ['HS256'] }).
- CWE-347

### Обход каталогов — путь к файлу берётся из запроса
- Где: `src/server/users.js:33`
- Как исправить: Берите только имя файла (path.basename), проверяйте его по белому списку и убедитесь, что итоговый путь остаётся внутри нужной папки.
- CWE-22

### Пароль или ключ записан прямо в коде
- Где: `src/server/users.js:35`
- Как исправить: Перенесите значение в переменную окружения (process.env), смените пароль или ключ и не храните секреты в репозитории.
- CWE-798

### SSRF — сервер запрашивает адрес, который прислал пользователь
- Где: `src/server/users.js:40`
- Как исправить: Разрешайте только заранее известные домены, запрещайте внутренние адреса (localhost, 10.x, 169.254.169.254) и редиректы.
- CWE-918

### NoSQL-инъекция — в $where подставляются значения, база выполнит их как JavaScript
- Где: `src/server/users.js:49`
- Как исправить: Уберите $where и используйте обычные операторы запроса: { userId: id, stocks: { $gt: threshold } }, предварительно приведя значения к числам.
- CWE-943

### Выключено автоэкранирование шаблонов — любой вывод данных становится XSS
- Где: `src/server/users.js:53`
- Как исправить: Верните autoescape: true. Где нужен HTML, отмечайте его явно (filter safe) и очищайте через DOMPurify.
- CWE-79

### Supabase: у таблицы public.profiles не включён RLS
- Где: `supabase/migrations/001_init.sql:1`
- Как исправить: Без RLS таблицу читает и меняет любой, у кого есть публичный anon-ключ из вашего сайта. Добавьте alter table public.profiles enable row level security; и политики доступа к своим строкам.
- CWE-284

### Открытый редирект — адрес перехода берётся из запроса

Логику прав доступа (может ли пользователь A открыть данные пользователя B), настройки облачных консолей и платёжных систем, работу сайта под нагрузкой. Код проверялся на вашем компьютере и никуда не отправлялся; для проверки зависимостей в базу OSV ушли только названия и версии пакетов.
